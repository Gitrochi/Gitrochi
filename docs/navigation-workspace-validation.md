# 작업 탐색과 협업 화면 검증

2026-10-26 · macOS SwiftUI / Windows Tauri·React 공통 구현

## 왼쪽 메뉴

스크린샷의 작업 기능과 기존 AI·에이전트·워크트리·도구를 유지하면서 저장소 작업은 왼쪽 **저장소** 한곳에 모았다. 본문의 **변경 내용·커밋·브랜치·비교·리베이스·Code** 탭에서 전환하며, 기본 왼쪽 메뉴에는 이 여섯 작업을 따로 나열하지 않는다. **저장소 목록**은 최근 로컬 저장소와 원격 저장소를 찾는 별도 화면이다.

자주 쓰는 작업은 현재 탭의 고정 버튼이나 왼쪽 **저장소 바로가기 선택**에서 골라 왼쪽 메뉴에 추가한다. 고정 설정은 창과 저장소 사이에 공유하며, 바로가기를 제거해도 열린 탭이나 기능은 유지한다. 검색(⌘K / Ctrl+K)으로 고정하지 않은 작업도 바로 열 수 있다. 설정은 아래에 고정한다.

저장소마다 마지막 내부 탭을 기억하고 뒤로/앞으로 이동에도 탭 선택을 복원한다. 기존 작업별 이동과 단축키는 통합 저장소의 해당 탭으로 연결한다. 저장소가 필요한 화면은 저장소를 열기 전 비활성화하고 이유를 표시한다. GitLab에서는 MR·Pipelines·Groups·Snippets 명칭을 쓴다.

| 화면 | 앱에서 할 수 있는 일 |
|---|---|
| 홈 | 열린·최근 저장소, 변경/앞섬/뒤처짐, 열기·복제·새 저장소·계정 시작 |
| 저장소 목록 | 로컬 목록과 연결한 서버 계정의 저장소 검색·페이지 탐색·복제 |
| 변경 내용 | 파일/줄/덩어리 diff, 스테이지·커밋, 기존 AI·계정 점검·충돌 편집 |
| 커밋 | 그래프·검색·다중 선택·커밋 상세·파일 이력·줄/함수 이력·기존 커밋 작업 |
| 브랜치 | 로컬/원격/태그/스태시 검색, 최근 활동·업스트림·병합 여부, 고정·숨김, 체크아웃·이름 변경·병합·리베이스·Push·삭제 |
| 비교 | 브랜치/태그/커밋 두 시점 비교, 공통 조상 기준, SHA 고정, 파일 목록·diff |
| 리베이스 | 새 기준점 검토·실행, 커밋 정리 계획, 진행 중 계속/중단, 결과 비교 |
| Code | 고정 리비전의 폴더/경로 검색·텍스트/이미지·파일 이력·blame·작업 변경 |
| 수신함 | 현재 저장소 또는 선택한 계정 전체의 알림/할 일, 상세·지원되는 읽음 처리 |
| 내 작업 | 작성·담당·리뷰 요청을 현재 저장소 또는 계정 전체에서 조회 |
| PR/MR | 검색·상태·페이지 탐색, 대화·파일 diff·줄 댓글/일괄 리뷰, 편집·상태 변경·병합 점검 |
| 이슈 | 목록·검색·필터·페이지 탐색, 생성·수정·대화·댓글·닫기·다시 열기 |
| Actions / Pipelines | 기존 실행/작업 조작, 단계·상태, 선택한 작업 로그 보기·복사 |
| 릴리스 | 목록·상세·자산/다운로드 연결, 생성·편집·게시·삭제 |
| 프로젝트 | GitHub Projects v2 항목·단일 선택 상태 필드 변경·기존 이슈 추가, GitLab 보드 범위와 라벨 열 이동 |
| 조직 / 그룹 | 계정·서버 선택, 조직/그룹·구성원·저장소 탐색·복제 연결 |
| gist / 스니펫 | 여러 파일 열기·생성·편집·삭제, GitHub 별표 |
| 저장소 AI 도우미 | 본문에서 읽기 전용 저장소 질문·미리보기·도구 사용 기록·취소 |
| 에이전트 / 워크트리 | 기존 세션과 워크트리 관리, 새 세션·워크트리·터미널 연결 |
| 도구 및 진단 | 설정 진단·명령 안내·코드 구조 탐색, 복구/LFS/Submodule/Bisect·외부 AI MCP 연결 |

계정 전체 수신함·내 작업, 프로젝트·조직·gist는 로컬 저장소 없이도 연결한 계정을 선택해 쓸 수 있다. 저장소별 릴리스와 Git 작업은 로컬 저장소의 원격을 사용한다.

## 설정 정리

설정에는 계정/API 연결·Git 이름/이메일·SSH, AI 제공자·규칙, 실행 파일 위치, 화면, 업데이트, 터미널 명령 설치를 둔다. 진단·명령 안내·언어 지원·인덱스 설명·구조 탐색은 왼쪽 도구에서 연다. 이전 안내 진입 경로는 호환성을 위해 유지한다. 앱이 임의로 계정 잠금·인증·SSH 설정을 바꾸지 않는다.

## 실제 범위와 차이

- GitHub Projects v2에는 프로젝트 읽기/쓰기 권한이 필요하다. 단일 선택 필드 외의 고급 필드 편집·프로젝트 생성/관리·자동화는 브라우저에서 이어간다. GitLab 보드는 범위 조건을 서버 질의에 반영하고 라벨 열을 이동하며, 담당자 등 라벨이 아닌 열 관리는 브라우저에서 진행한다.
- 허브 검색은 불러온 페이지 안에서 필터링한다. 더 불러온 뒤 검색 범위가 넓어진다는 안내를 표시한다. 서버 저장소 검색과 이슈 검색은 서버 검색이다.
- GitLab 릴리스는 GitHub draft/prerelease와 방식이 다르고 스니펫 별표도 제공하지 않는다. 화면에서 차이를 안내한다. 릴리스 자산은 목록과 다운로드 연결을 지원하며 파일 업로드 관리 화면은 제공하지 않는다.
- 잘린 gist 원문은 편집을 차단한다. 수정·삭제 직전에 서버 내용을 다시 읽어 다른 변경을 덮지 않는다. 새 릴리스/gist 생성 응답이 유실되면 결과 확인 안내 후 원격 목록을 새로 확인하게 한다.
- CI 로그는 최대 2MB 텍스트이다. ANSI 제어 문자, 연결 토큰과 알려진 토큰 형태·민감 키 패턴을 가려 표시한다. 모든 비밀을 식별한다는 보장은 없으므로 서버의 로그 마스킹도 필요하다. GitHub 작업 로그 다운로드의 허용된 HTTPS 이동만 따르고 서버가 바뀌면 인증 헤더를 제거한다. GitLab은 다른 서버 이동을 차단한다.
- Code는 Git 객체의 스냅샷을 읽으며 실행·수정하지 않는다. 심볼릭 링크나 하위 모듈을 따라 작업 폴더 밖의 파일을 읽지 않는다. 큰 파일·바이너리는 크기 제한과 안내를 제공한다.
- 저장소 전환과 같은 경로 재오픈을 별도 세대로 처리한다. 오래된 응답·확인창과 중복 실행은 새 저장소에 적용되지 않는다. AI 문맥 준비 중 화면을 떠난 경우에도 복귀해 다시 준비할 수 있다.

## 검증

다음은 최초 개별 메뉴 배치 시점의 검증 기록이며, 통합 저장소 탐색의 후속 검증은 아래에 덧붙였다.

- macOS arm64 개발 앱 전체 컴파일 및 ad-hoc 서명 검증.
- Windows 프런트엔드 전체 빌드, TypeScript, 전체 Vitest 360개 검사. 병행 중인 Rust 공통 코어 변경에 맞춰 네이티브 메뉴 검사에도 공통 라이브러리를 연결했다. 동시 검사로 라이브러리가 갱신돼도 컴파일 입력이 바뀌지 않도록 링크할 사본을 고정했다. Rust 백엔드는 macOS 호스트에서 컴파일하고 CI 로그 이동 경계 검사를 실행했다.
- 네이티브 메뉴 회귀: 21개 목적지 접근 조건, 배경 선택 갱신의 화면 유지, 명시적 문서/리뷰 이동, 뒤로/앞으로 분기·길이 제한, 독립 설정 저장소의 리포지터리별 복원.
- 네이티브 독립 검사: 실제 임시 Git 트리/객체·파일 경계, 허브 API·페이지·오래된 문맥·gist 충돌, 이슈 CRUD·계정 전체 API·CI 로그 가림, 오래된 확인창과 한 번 실행.
- 실제 React 화면 검사(5개 흐름 묶음 통과, 예상 밖 외부 호출 0회): 메뉴 21개·검색·단축키·설정 고정, 브랜치/원격/태그/스태시·고정/숨김, 본문 비교/리베이스/Code, 릴리스 편집 확인·프로젝트 상태/이슈·조직 복제·gist 별표/삭제 취소, 홈·원격 검색/복제·이슈 대화·계정 전체 수신함/내 작업·CI 로그·진단.
- 홈·브랜치·Code·릴리스·프로젝트·도구와 변경 내용·커밋·커밋 diff·PR 대화·PR diff·계정 전체 수신함의 밝은/어두운 테마, 1440×1000·1080×800 배치 48조합을 독립 브라우저에서 검사했다. 버튼 경계와 파일 제목 너비, PR 내용 겹침, 사이드바를 스크롤할 때 설정 버튼 고정도 확인했다. 화면과 구조 검사 결과는 [캡처 폴더](screenshots/navigation-workspace)에 보존한다.

외부 서비스·프로세스·토큰·파일 응답은 가짜 데이터로 대체했고 실제 인증, 원격 변경·Push·유료 AI 호출은 수행하지 않았다. Windows 기기에서의 설치/실행과 실계정 권한별 연동은 이 macOS 작업 환경에서 검증하지 않았다. 이 작업으로 릴리스를 게시하거나 설치본을 교체하지 않았다.

## GitHub 로그인 코드가 보이지 않던 문제

GitHub CLI의 클립보드 자동 복사 설정이 켜져 있으면 코드 안내 문구가 달라지는데, 기존 도우미는 일반 안내 문구만 읽었다. 코드가 발급됐어도 앱에는 `deviceCode: null`이 전달되어 브라우저를 열지 못했다. [공식 CLI의 두 출력 형식](https://github.com/cli/cli/blob/v2.102.0/internal/authflow/flow.go#L43-L54)을 좁게 인식하도록 수정했다. 사용자 클립보드·GitHub 계정 설정은 변경하지 않는다.

대기 응답에는 선택적 `phase`를 추가해 다른 로그인 대기(`queued`), 코드 준비(`preparing`), 브라우저 승인(`approval`)을 구분한다. 실제 인증 시작 후 60초 동안 코드가 없으면 실패로 전환하며, 다른 로그인 차례를 기다린 시간은 이 제한에서 제외한다. 전체 로그인 제한은 15분이다. 앱에도 준비/승인 안내·수동 페이지 열기·실패 후 재시도·대기 제한을 제공한다.

격리된 가짜 CLI로 일반/클립보드 형식·설정 보존·잘못된 코드 차단·준비 기한·대기열을 검사했다. Windows 실제 React 화면에서는 시작 응답에 코드가 있는 경우, 코드 없는 준비, 대기열, 상태 조회 실패, 취소 뒤 늦은 응답과 가상 시계의 만료를 검사했다. Mac의 독립 진행 상태 검사도 통과했다. 기본 설정 진단은 문제 0개였다. 실행 중인 Mac 앱의 도우미를 갱신한 뒤 기존 대기 창에서 코드와 브라우저 열기 버튼이 표시되는 것을 확인했다. 실제 로그인 코드는 검증 산출물에 저장하지 않으며 GitHub 승인 조작은 사용자에게 맡긴다.

이번 로그인 수정의 최종 검사: CLI 전체 225개, 로그인·공통 계약 22개, Windows 전체 365개, Mac 진행 상태·계정 일치 검사와 독립 출력 폴더의 전체 앱 빌드가 통과했다. 실행 중인 로그인 창은 유지했다.

## 화면 정돈 최종 검증

- macOS arm64 앱 전체 빌드와 엄격한 번들 서명 검사를 통과했다. 한국어 실앱에서 저장소 탭 전환, 브랜치 바로가기 고정·해제, 기본 통합 메뉴 복원을 확인했다.
- Windows 전체 단위 검사 372개(37개 파일), TypeScript, 프런트엔드 빌드가 통과했다. 이 환경에서 Windows 네이티브 실행을 직접 확인하지는 않았다.
- 실제 화면 72조합(800·1080·1440px, 밝은/어두운 테마)과 패널·긴 이름·팝오버 94사례가 통과했다. 파일 목록을 커밋 작성칸이 누르지 않게 작은 창에서는 전체 목록 영역을 스크롤하고, 검색·작업 버튼은 패널 폭에 맞춰 줄바꿈한다. 대표 캡처와 결과는 [통합 화면 검증](screenshots/unified-workspace/verification.json)에 보존한다.
- PR 파일 검토 왕복 시 댓글과 제목 편집을 유지한다. 실제 React 회귀 검사에서 같은 입력 요소와 작성 내용 보존, 다른 PR 선택 시 초기화, 예상 밖 외부 호출 0회를 확인했다.
- GitHub 승인과 CLI 계정 확인은 완료됐으나 실앱 키체인 저장은 macOS 인증 오류 `-25293`으로 거부됐다. 실패를 성공으로 표시하거나 계정을 저장하지 않으며, 오류 단계와 안전한 숫자 코드만 안내한다. 키체인 잠금 해제·암호 입력은 사용자가 직접 진행한다. Git 설정 진단은 문제 0개였다.

키체인 후속 확인: 사용자가 로그인 키체인을 직접 다시 인증한 뒤 앱의 GitHub CLI 계정 가져오기가 성공했다. 승인한 계정과 일치하는 계정 1개가 연결됨으로 표시되고 앱 설정에도 저장됐으며, 앱에서 해당 계정의 원격 저장소 목록을 정상 조회했다. 검증한 독립 빌드를 한국어 저장소 목록 화면에 열어 두었다.

### 저장된 계정 접근 중 화면 응답

- `SecItemCopyMatching`은 호출 스레드를 막으므로 저장된 계정의 토큰은 메인 액터에서 직접 읽지 않는다. [Apple API 설명](https://developer.apple.com/documentation/security/secitemcopymatching(_:_:))에 따라 읽기·쓰기·삭제를 별도 직렬 큐에서 실행한다.
- 자동 읽기는 Keychain UI를 허용하지 않는다. 기존 file-based 항목은 Data Protection 키체인의 인증 UI 옵션을 따르지 않을 수 있어, 이 큐 안에서만 공식 `SecKeychainGetUserInteractionAllowed`/`SecKeychainSetUserInteractionAllowed`로 기존 정책을 보존하고 복원한다. 잠금 상태·접근 제어 목록·인증 대상을 바꾸지 않는다. 이 legacy 호환 경로의 두 API에는 SDK deprecation 경고가 남는다.
- 승인이 필요한 경우 우측 계정 팝오버의 **저장된 계정 접근 허용**을 사용한다. 사용자가 누르면 백그라운드에서 macOS 승인을 기다리고, 서버의 동일 사용자를 검증한 뒤 메모리 캐시와 계정 revision을 갱신한다. 로컬 Git 화면은 계속 사용할 수 있다.
- 초기 읽기 결과가 새로 승인한 토큰을 덮거나 해제한 계정을 되살리지 않게 요청별 세대를 확인한다. 저장 중 해제한 계정과 후속 연결 요청도 다시 확인한다.
- `bash macos/Tools/test-credential-access.sh`: 가짜 Security 함수만 사용해 무음/대화형 정책의 복원, 큐 직렬화, 대기 중 메인 액터 진행, 읽기 합치기, 승인이 필요한 계정의 무한 재조회 방지, 새 저장/해제 뒤의 오래된 결과 폐기를 통과했다. 실제 키체인·계정·인증은 변경하지 않았다.
